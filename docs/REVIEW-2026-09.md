# Production speed review and first-books plan (September 2026)

Written 2026-09-22 from a full read of the repository and timed runs of the
pipeline. It records why a book takes too long to make, what to change
(ranked), and which books to make first. It is a plan: nothing in section 2
has been built yet unless it is marked done.

The goal: eventually produce about one book a day from a few simple prompts.

---

## 1. Where the time goes

### The software is not the bottleneck

Timed on the demo book (24 pages):

| Step | Time |
| --- | --- |
| `status` / `next` / `qa` | about 0.3 s each |
| Render one page | about 1.3 s |
| Render all 24 pages | about 12 s |
| Assemble the interior PDF | about 0.6 s |
| Full test suite | about 2 min 47 s (all passing) |

An 80-page book renders and assembles in well under a minute. The rest of the
time is spent waiting on an agent or on the operator.

### The process is

1. **About 400 tasks per book, done one after another.** `bookfactory next`
   (`bookfactory/core/tasks.py`) finishes each page completely before it lets
   anything start on the next. For each page that means: spec, register
   artwork, draw, approve the artwork, render, approve the page. The demo book
   took 78 tasks for 24 pages. For 80 pages with about 40 illustrations:

   | Stage | Tasks |
   | --- | --- |
   | Setup (brief, voice, manuscript, bibles, six references, four locks) | ~30 |
   | Page specs | 80 |
   | Illustrations (register, draw, approve × 40) | 120 |
   | Page renders and approvals | 160 |
   | QA, assembly, cover | ~11 |

   Each task is at least one agent turn, and usually a commit and push too.
2. **The default policy stops for the operator almost every time.** A book
   made with `bookfactory create` defaults to `checkpointed`
   (`ProductionPolicy` in `bookfactory/core/models.py`). Every approval and
   lock then waits for the operator: about 150 stops per book. The runner
   book is in this mode.
3. **Illustrations need a person to carry them.** Only ChatGPT generates
   images, by hand in chat. There is no image API in the pipeline.
4. **The cover is a one-off script for each book**
   (`books/*/cover/build_cover_v1.py`). There is no `cover build` command.
5. **Read-only commands write files.** Running `status`, `next` and `qa` on
   the demo book changed 6 files. Combined with pushing to `main` after every
   task (including images of about 2 MB each), this creates commit churn and
   conflicts. 48 binary files are stored more than once (the same picture as
   draft, "native" and approved copies). *Read-only half fixed 2026-09-22:
   `status`, `next`, `task` and `validate` write nothing (`next --persist`
   refreshes the cached task on request), and `qa` writes only its report.*
6. **Contradictory rules.** `AGENTS.md` said never to run
   `assemble`/`preflight` without the operator asking, while autonomous mode
   said to keep going. *Fixed 2026-09-22: these commands now follow the
   task's `mode`.*

## 2. What to change, ranked by payoff

| # | Change | Benefit |
| --- | --- | --- |
| 1 | Make `visual_checkpoint` the default policy, and let an existing book switch policy. | The operator stops about twice per book (visual set and cover) instead of about 150 times. Smallest change, biggest win. |
| 2 | Work in phases, not page by page: `next --batch`, `spec --from-file` for many pages, `render --all --submit`, and approving every draft that passes its measured checks in one command. | About 400 turns become about 15. Illustrations can run in parallel. |
| 3 | Merge the page plan and specs into one file, and register assets automatically from each spec's `illustration.asset_id`. | Removes about 120 small tasks. The page plan is written in one pass from the manuscript. |
| 4 | Connect an image API: `bookfactory illustrate --all` sends each task and its references, checks the pixels, and retries automatically (retry logic exists). | Illustrations take minutes instead of hours, run in parallel, with nobody carrying files. Needs an API key; costs per image. |
| 5 | Add `bookfactory cover build`, reusing the HTML renderer with a cover template fed from `cover/cover.json`. | Covers take seconds and are consistent across a series. |
| 6 | Series presets: reuse a locked voice bible, visual bible, design tokens and reference set from an earlier book. | Book 2 onwards skips most of visual development, the slowest creative stage. This is what makes a book a day sustainable. |
| 7 | One-prompt start: `create-from-idea` drafts the 12 intake answers from one sentence and asks only what is genuinely unclear. | Simple prompts in, no questionnaire round trip. |
| 8 | A single `bookfactory produce <book>` loop, run by a scheduled Claude Code routine: text from the Claude API, images from #4, stopping only at the operator's checkpoints. | Start in the morning; it runs until the visual check, then to final review. |
| 9 | Make read-only commands read-only, push once per phase, and store each binary once (or use Git LFS). *Read-only half done 2026-09-22; pushing per phase and single-copy binaries remain.* | Fewer commits and conflicts; a smaller, faster repository. |
| 10 | Remove contradictions between rules and docs. *Done 2026-09-22 (restricted commands, branch policy, `lock --autonomous`, read-only commands, integration roles, stage count, requirements files).* | Agents stop pausing for permission they already have. |

Safeguards to keep as they are: no words inside generated images, all type
set by the renderer, visual lock before page production, checksums, and the
KDP preflights.

Suggested order: #1, #2, #9, #10 and the demo-script fix first (quick), then
#3, #5 and #7, then #4, #6 and #8.

Estimated day under this plan (an estimate, not a measurement): writing and
specs 30-45 minutes of model time; about 40 images in parallel 10-20 minutes;
render, QA, assembly and cover a few minutes; plus two operator reviews of
about 10 minutes each.

### Smaller fixes found during the review

All three done 2026-09-22.

- `scripts/build_demo_book.py` fails at the `cover_preflight` gate ("Full-wrap
  cover awaits operator approval"). It was not updated when covers became
  required. *Done: the script now walks the whole cover flow.*
- The cover check (`bookfactory/core/cover.py`, `check_pdf`) requires an
  artwork image, so text-only covers cannot be submitted or approved through
  Book Factory. *Done: `bookfactory cover artwork <book> --mode none --by
  <operator>` records a text-only cover (`"artwork": "none"` in
  `cover/cover.json`).*
- `lock` has no `--autonomous` flag, so a lock made under an autonomous policy
  is marked only by its note, not by a distinct audit entry as `approve` is.
  *Done: `lock --autonomous`, same gate and audit marker as `approve`.*

## 3. Which books to make first

Research done 2026-09-22 using web search. Amazon's best-seller pages blocked
automated access, so competition was judged from search results. Check the
Amazon listings by hand before committing to a title.

### Timing

- Shoppers start buying for Christmas in late October and early November.
  Amazon UK's last order dates are about 21-22 December.
- KDP paperback review takes 3-5 business days, and longer in Q4. There are no
  print pre-orders.
- Target: live by **31 October**. The hard limit is about **15 November**.
- Keep first books simple: 60-80 pages, black-and-white interior, colour
  cover, about 12-20 illustrations.

### Order

0. **The runner book: publish now** (not ranked; it is nearly finished). The
   80-page interior exists. Upload pack:
   `books/runners-guide-to-normal-conversation/releases/KDP-UPLOAD.md`. Text-only
   cover chosen 2026-09-22. Running is a crowded gift category (for example
   Ricky Woods' "Funny Sports Gag Gifts" series), but the "can't stop talking
   about it" angle is aimed at the person who buys the gift.
1. **Padel: first pick.** About 860,000 people played in Britain in 2025,
   more than double 2024 (LTA), and UK search interest is up 121%. No
   illustrated humour book was found; only socks and tote bags. The same
   joke as the runner book in a new setting, so the design can be reused
   (quickest second book). Risk: mainly a UK and European market.
2. **Golf: biggest market, sells all year.** Also sells for Father's Day,
   birthdays and retirements, so June is a fallback launch. Crowded (Ricky
   Woods, Golfwell), but mostly text-only joke lists; a well-illustrated book
   stands out. The demo book's golf-addict manual is a start. Needs a steady
   Amazon Ads budget.
3. **Hyrox (fitness racing).** UK participants rose from about 7,400 to more
   than 97,000 a season. Only a low-effort "100 jokes" book exists. Risk:
   "HYROX" is a trademark, so the title must use generic terms, which makes it
   harder to find.

Alternatives: retirement (sells all year, a softer joke) and office Secret
Santa (high Christmas volume, but not the "that's literally him" format).

### Series

Make one series, *The [Hobby] Obsessive's Guide to Normal Conversation*, with
one art style, one design and one structure. Change #6 above is what makes it
fast, and each title's reviews and ads help sell the others.

Suggested schedule: runner live this week; padel by 31 October; golf by
15 November (or Father's Day if it slips); Hyrox, cycling and pickleball (US)
in the new year.

### Pricing reference

On Amazon.com, 24-108 black-and-white pages cost a flat $2.30 to print. The
royalty is 60% of list price at $9.99 or more, and 50% below that (KDP rates
checked July 2026). At $12.99 that is about $5.49 per copy.

### Expectations

Most gift books on Amazon sell modestly. A niche title selling a handful of
copies a day in December, with ads behind it, is a good first result. Treat
each title as a test and reorder the series around whatever sells.

When uploading, KDP asks whether text and images are AI-generated. Answer
honestly; Amazon says the answer is not shown to buyers and does not by
itself affect whether the book is available.
